# FitJourney 2.0 — Sistema Completo\n\n**Data:** 23 de Maio de 2026  \n**Status:** ✅ ARQUITETURA BLINDADA  \n**Próximo:** Sprint K — Testes Forenses\n\n---\n\n## Visão Geral do Sistema\n\nFitJourney 2.0 é um **sistema operacional clínico de nutrição** que transforma a forma como nutricionistas criam, gerenciam e entregam planos de refeição.\n\n```\n┌─────────────────────────────────────────────────────────────┐\n│                    FITJOURNEY 2.0                           │\n├─────────────────────────────────────────────────────────────┤\n│                                                             │\n│  CAMADA 1: AUTORIA CLÍNICA (Editor V3)                     │\n│  ├─ Nutricionista cria planos                              │\n│  ├─ Busca alimentos (NOSFoodSearch)                        │\n│  ├─ Cria receitas (RecipeBuilder)                          │\n│  ├─ Cria combos/marmitas (ComboBuilder)                    │\n│  └─ Macros calculadas em tempo real                        │\n│                                                             │\n│  CAMADA 2: COMPILAÇÃO (Sovereign Compiler)                 │\n│  ├─ Congela todos os valores calculados                    │\n│  ├─ Cria snapshot imutável                                 │\n│  └─ Ponto de fechamento (publicação)                       │\n│                                                             │\n│  CAMADA 3: ENTREGA (Patient App)                           │\n│  ├─ Paciente visualiza plano                               │\n│  ├─ Faz substituições (sem recálculo)                      │\n│  ├─ Vê macros congelados                                   │\n│  └─ 100% PASSIVO (sem engine)                              │\n│                                                             │\n└─────────────────────────────────────────────────────────────┘\n```\n\n---\n\n## Componentes Principais\n\n### 1. NOS — Nutrition Operating System\n\n**Responsabilidade:** Autoria clínica + cálculos nutricionais\n\n**Tabelas:**\n- `nos_foods` — Base unificada de alimentos (TACO + USDA + custom + brand)\n- `nos_recipes` — Receitas versionadas\n- `nos_meal_combos` — Marmitas, refeições prontas, combos\n- `nos_nutritionist_library` — Biblioteca pessoal do nutricionista\n\n**Componentes:**\n- `NOSFoodSearch` — Busca soberana de alimentos\n- `RecipeBuilder` — Criar receitas\n- `ComboBuilder` — Criar combos/marmitas\n- `calcEngine` — Cálculos nutricionais (TypeScript puro)\n\n**Invariantes:**\n- ✅ Engine é puro (sem side effects)\n- ✅ Snapshots são imutáveis após publicação\n- ✅ Separação de camadas\n- ✅ RLS isolado por tenant\n- ✅ Índices de performance\n\n### 2. Sovereign Snapshot V3\n\n**Responsabilidade:** Congelamento de dados após publicação\n\n**Tabela:** `meal_plans.snapshot` (JSONB)\n\n**Conteúdo:**\n- Meals com items congelados\n- Macros congelados\n- Version history\n- Source recipe version\n\n**Invariantes:**\n- ✅ Imutável após publicação\n- ✅ Self-contained (não referencia dados externos)\n- ✅ Versionado\n- ✅ Histórico preservado\n\n### 3. Patient App\n\n**Responsabilidade:** Visualização passiva de planos\n\n**Função:** `extractMealsFromSnapshot()`\n\n**Invariantes:**\n- ✅ ZERO cálculo\n- ✅ ZERO inferência\n- ✅ ZERO acesso a nos_foods, calcEngine, etc\n- ✅ Lê APENAS de snapshot\n\n---\n\n## Fluxo de Dados\n\n### Fluxo de Autoria (Editor V3)\n\n```\n1. Nutricionista abre Editor V3\n   ↓\n2. Busca alimento via NOSFoodSearch\n   ↓\n3. Seleciona alimento\n   ↓\n4. Edita gramagem\n   ↓\n5. calcEngine recalcula macros em tempo real\n   ↓\n6. Nutricionista cria receita (RecipeBuilder)\n   ↓\n7. Nutricionista cria combo (ComboBuilder)\n   ↓\n8. Nutricionista adiciona combo ao plano\n   ↓\n9. Nutricionista clica \"Publicar Plano\"\n   ↓\n10. buildSovereignSnapshot() congela TODOS os valores\n    ↓\n11. Snapshot gravado em meal_plans.snapshot (JSONB)\n    ↓\n12. Plano publicado (immutable)\n```\n\n### Fluxo de Entrega (Patient App)\n\n```\n1. Paciente acessa Patient App\n   ↓\n2. Visualiza plano publicado\n   ↓\n3. extractMealsFromSnapshot() lê snapshot\n   ↓\n4. Paciente vê meals com macros congelados\n   ↓\n5. Paciente faz substituição\n   ↓\n6. Substituição é registrada (sem recálculo)\n   ↓\n7. Macros permanecem congelados\n   ↓\n8. Nutricionista vê histórico de substituições\n```\n\n---\n\n## Boundaries Arquiteturais\n\n### ✅ PERMITIDO\n\n**No Editor V3:**\n```typescript\nimport { calcEngine } from Security)\n\n**nos_foods:**\n- Global (tenant_id NULL) visível para todos\n- Custom/brand visível apenas para o tenant dono\n\n**nos_recipes:**\n- Visível apenas para o nutricionista dono\n- Público (is_public = true) visível para o workspace\n\n**nos_meal_combos:**\n- Visível apenas para o nutricionista dono\n- Público (is_public = true) visível para o workspace\n\n**nos_nutritionist_library:**\n- Visível apenas para o nutricionista dono\n\n### Isolamento de Tenant\n\n- Cada tenant tem seus próprios alimentos custom\n- Cada nutricionista tem suas próprias receitas/combos\n- Dados globais (TACO/USDA) são compartilhados\n- RLS garante isolamento em nível de banco\n\n---\n\n## Performance\n\n### Índices Críticos\n\n**nos_foods:**\n- ordenação\n- `nos_meal_combos_type_idx` — filtro por tipo\n- `nos_meal_combos_slot_idx` — filtro por slot de refeição\n\n**nos_nutritionist_library:**\n- `nos_library_priority_idx` — biblioteca com priorização\n- `nos_library_type_idx` — filtro por tipo\n\n### Tempos de Resposta\n\n- Busca de alimento: < 100ms\n- Listagem de receitas: < 100ms\n- Listagem de combos: < 100ms\n- Cálculo de macros:
